TESTING METHODOLOGY NOTES (not gameplay bugs, worth recording)
=========================================================================
- Hit four separate game_eval crashes this session (each recovered via the
  established project_manage(stop) + project_run cycle, per the standing
  eval-fragility finding), all self-inflicted testing mistakes rather than
  game bugs:
    1. Calling `Brewery.add_risk(...)`/`Brewery.has_method(...)` statically
       on the class_name instead of `BrewEngine.current_brewery.add_risk(...)`
       — a compile-time parser error that still parks the live game.
    2. Chaining a restart button's emit_signal("pressed") with an immediate
       node lookup on the very next line of the same eval call — the lookup
       hit the GUI mid-teardown/rebuild and threw a null-instance error.
       The exact same lookup worked fine as its own separate eval call
       moments later with a fresh run, so this reads as a same-call-chaining
       artifact, not a real restart-flow bug — not confirmed either way
       against the actual "Uusi yritys" bankruptcy-restart path specifically,
       since I only re-verified via a fresh main-menu start.
    3. Assuming `TooltipFactory.make_wrapped_tooltip()` returns the Label
       directly and reading `.autowrap_mode` off it — it actually returns a
       PanelContainer wrapping the Label as its child. Confirmed by reading
       tooltip_factory.gd after the crash; the function's actual behavior
       (autowrap + 260px cap only once text needs it) is unchanged from last
       session's already-passing verification, so this wasn't re-tested live
       a third time — no reason to expect it broke.
    4. (Carried from last session, not repeated) an in-eval polling loop
       over a Tween-driven walk can EVAL_HUNG faster than the walk itself
       resolves.
  All four this session were caught and recovered without losing more than
  the single triggering call. Updated the standing eval-fragility memory
  with all of these so future sessions don't re-spend the same crash cycles.
- DevConsole commands (iddqd, group <name>, day, raid, sell [n] <style>,
  vie <style> <bar>, money/rep/risk <n>) ran cleanly every single time with
  zero crashes, in sharp contrast to raw eval above — this is now the
  preferred test surface for anything it covers.
- A forced string of "day" advances (4 in a row via DevConsole, no real
  play in between) drained the treasury to bankruptcy ("KONKURSSI!", day 3,
  #7 on the leaderboard) purely from daily upkeep costs with zero income —
  expected fallout of the test methodology (spamming day-closes with no
  actual brewing/selling), not a discovered bug. The game-over screen itself
  rendered correctly and the "Uusi yritys" restart flow worked.
- get_ui_elements' polled RichTextLabel .text does NOT reflect content
  added via append_text() (DevConsole's own log) — Godot only reflects a
  direct assignment there. Read the node's own tracked array/state instead
  (here, `_command_history`) when you need to see what a RichTextLabel-based
  log actually contains.
